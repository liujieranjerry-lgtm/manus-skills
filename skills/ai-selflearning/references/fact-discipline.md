# Fact Discipline：企业级信息必须可核验

“企业级密度”最容易引入的错误，是把模型记忆里的推测写成笃定事实。本节是写作后必过的门禁。

## 断言分类

动笔和核验时，把每一句具体断言归入三类，三类不得混成同一个语气：

1. **原文明确的**：源材料里直接写了什么。改写时保留但也要复核是否属实（原文也会错）。
2. **已有知识补充**：模型基于训练记忆补充的概念、背景。概念层可保留；事实层必须降为待核验。
3. **需实时核验的厂商事实**：一切“谁家产品做了什么、什么时间、什么数字”。

区分概念层与事实层：

- **概念层**（术语、边界、原理、分类）：要求准确、一致、解释清楚，不要求逐条引源。
- **事实层**（具体厂商、产品名、版本号、日期、合作关系、数值、API/包名、定价、功能上限）：每条都必须有出处或经过核验。

## 核验流程

1. **列断言清单**：草稿完成后，把全文事实层断言逐条列出（claim ledger），每条标注“来自原文 / 记忆补充 / 待核验”。
2. **逐条核验**：原文有的对照原文；不在原文的用权威来源核验（官方文档、官方公告、官网、仓库、可靠一手资料）。核验工具不可用时，把该条降级，不得跳过。
3. **处置**：
   - 核验通过 → 保留，语气可以笃定。
   - 查不到或来源矛盾 → 改写为“据我了解”“需要确认”，或直接删掉细节；如果该断言是文章核心且无法核验，交付时明确告诉用户。
   - 宁可少写、写明出处，不可写得漂亮却没有来源。
   - 把核验结论整理成 3–5 条交付说明：哪些关键断言来自材料、哪些是讲解性补充且已核验、哪些降级或存疑。这段说明放在给用户的交付信息里，不写入文章正文。
4. **忠实原文**：改写和增补不得曲解原文观点；增补必须与“原文说了什么”可区分，不得把“我的补充或推测”伪装成“原文这么说”。

## 通过标准

- 正文中不存在“以笃定语气出现但未核验”的具体断言。
- 读者把文章里任何一句具体断言拿去搜索，能找到与它一致的说法。
- 无法核验的核心事实要么已标注存疑，要么已告知用户。
