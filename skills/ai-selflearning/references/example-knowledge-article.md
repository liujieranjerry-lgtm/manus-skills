# 初识智能体：从一句模糊指令到第一个能干活的最小 Agent

> 材料来源：Datawhale Hello-Agents 第一章《初识智能体》（链接见文末）

你对着一个程序说：“帮我查一下今天北京的天气，然后根据天气推荐一个旅游景点。”它没有等着你一步步下命令，而是自己拆成“查天气→选景点→给答案”几步，中途还真的去查了实时数据，最后把结果整理成人话告诉你。这样的系统背后站着什么？它和一段写死的脚本、一个聊天机器人、一个固定的审批流程，区别到底在哪？

这一篇顺着材料的主线回答四个问题：智能体是什么、由什么构成、怎么从零搭出一个能跑的最小版本、以及放到真实应用里该把它当成“工具”还是“协作者”。

## 1. 一个定义，四个要素

材料给的定义很干净：**智能体（Agent）是能够通过传感器感知所处环境，并自主地通过执行器采取行动、以达成特定目标的实体。**拆开看，这个定义里有四样东西：

- **环境**：智能体所处的外部世界。对自动驾驶汽车，环境是动态的马路；对一个交易程序，环境是瞬息万变的金融市场。
- **传感器（Sensors）**：智能体感知环境的入口。摄像头、麦克风、雷达，以及程序世界里的各种 API（Application Programming Interface，应用程序编程接口——程序之间约定好的调用入口）返回的数据流，都是感知的延伸。
- **执行器（Actuators）**：智能体改变环境的出口。物理世界里的机械臂、方向盘，数字世界里的执行一段代码、调用一个服务。
- **自主性（Autonomy）**：最容易被忽略、却真正区分“智能体”和“脚本”的要素。脚本是被动执行预设指令的；智能体会基于感知和内部状态做独立决策，去接近自己设计目标。

把四者连起来，就得到一切智能体行为的底座：**感知→决策→行动→（环境变化）→新的感知**。这个闭环不是一句口号——后面的每一个概念，都是在这个环上做文章。

## 2. 智能体不是新概念：一条从“本能”到“学习”的演进线

在大语言模型（LLM，Large Language Model——在海量文本上训练出来、能理解和生成语言的模型）出现之前，AI 先驱已经探索了智能体几十年。材料的价值在于它把这条演进线整理成了五级台阶，每一级解决上一级的缺陷：

| 台阶 | 核心机制 | 它补上了什么 | 经典例子 |
|---|---|---|---|
| 简单反射智能体 | 工程师写死的“条件→动作”规则 | 起点，只能应付“当前感知就够决策”的情形 | 自动恒温器：室温高于设定值就制冷 |
| 基于模型的反射智能体 | 内部维护一个世界模型 | 感知不到的方面（遮挡、过去状态）仍能追踪 | 隧道里的自动驾驶车：摄像头看不到前车，内部模型仍维持对它的判断 |
| 基于目标的智能体 | 显式目标 + 搜索/规划 | 不再只是反应，而是主动选择通向目标的行动 | GPS 导航：用地图做世界模型，规划出最优路径 |
| 基于效用的智能体 | 给每个状态算“满意度”效用值 | 在多个冲突目标间权衡 | 导航不只求到达，还要时间最短、油耗最低、避开拥堵 |
| 学习型智能体 | 学习元件根据结果反馈修正决策策略 | 不依赖人类预设全部规则 | 强化学习（让程序在试错中根据奖励信号自己改进策略的训练方式）下棋：从随机落子到大量对弈中学会胜率更高的棋路 |

读这条线时最容易踩的误区是把它当成“旧东西”。材料提醒你相反：这五级不是被 LLM 淘汰的历史，而是理解 LLM 智能体的脚手架——今天一个现代智能体内部，可能同时包含“反射”的即时反应、“模型”的上下文追踪、“目标”的任务规划、“效用”的取舍，以及“学习”的经验修正。

顺着这条演进线，还能得到一套更系统的分类坐标：

**坐标一：内部决策架构**——从反应式到模型式、目标式、效用式，学习能力是能叠加在任意一层上的“元能力”。

**坐标二：时间尺度上的反应性 vs 规划性**。反应式智能体（Reactive Agent）几乎不规划，接到刺激立刻行动，速度快、开销低，适合安全气囊、高频交易这类毫秒级场景，代价是短视；规划式智能体（Deliberative Agent）行动前先推演未来、评估多条路径，适合需要长远眼光的任务，代价是慢和贵。材料指出，现实中的复杂任务两者都要，于是有了混合式智能体（Hybrid Agent）——常见做法是底层放快速反应模块、高层放审慎规划模块。值得注意：现代 LLM 智能体本身就是一种灵活的混合式，它把一个大目标拆成无数个“规划→反应”的微循环，在“思考-行动-观察”的节奏里同时获得远见和灵活。

**坐标三：知识以什么形式存在**。这是 AI 史上最持久的分歧：**亚符号主义（连接主义）**认为知识是海量神经元网络里学出来的统计模式，强在模式识别、弱在解释性（黑箱）；**符号主义**认为智能是对人类可读符号做逻辑操作，透明可追溯，但规则库一旦遇到没覆盖的例外就脆弱；**神经符号主义**则试图把两者接起来——模式识别负责“认出猫”，逻辑推理负责“证明为什么”。材料用卡尼曼的双系统理论给出了漂亮的对应：快速直觉的“系统 1”像亚符号主义，慢速审慎的“系统 2”像符号主义，而 LLM 智能体是神经符号主义的现实样本：内核是神经网络（由大量相互连接的简单计算单元构成、能从数据中自动学到规律的模型，即系统 1），工作过程却会产出思考、计划、API 调用这类可操作的符号（系统 2）。

## 3. 它靠什么运转：PEAS、Agent Loop 与 Thought-Action-Observation

### 3.1 先描述环境：PEAS

智能体不是悬浮的，它必须被放进一个“任务环境”里。材料引入的 PEAS 模型就是环境的四要素清单：**性能度量（Performance，怎么算做得好）、环境（Environment，它面对什么）、执行器（Actuators，它能做什么）、传感器（Sensors，它能感知什么）**。设计任何智能体之前，先用这四格把任务环境写清楚，比急着写代码重要得多。

真实环境通常比教科书复杂，材料列了四种特性，每种都直接决定设计取舍：

- **部分可观察**：旅行助手调航班 API，看不到所有航空公司的全部实时座位。推论：智能体需要记忆（记住查过什么）和探索（换日期再试）。
- **随机性**：两次查询的票价和余票可能不同。推论：要能处理不确定、监控变化、随时调整。
- **多智能体共存**：其他用户、自动化脚本、航司动态调价系统都在同一环境里行动，会抢走最后一张特价票。推论：要考虑竞争与策略。
- **序贯且动态**：今天的动作影响明天；环境在决策期间自己也在变。推论：感知-思考-行动-观察必须快速迭代，不能一锤定音。

### 3.2 运行机制：Agent Loop

在环境之上，智能体的工作方式是同一个循环：**感知（Perception）→ 思考（Thought）→ 行动（Action）→ 环境状态变化 → 新观察（Observation）→ 回到感知**。对 LLM 智能体来说，“思考”又细分成两件事：**规划**（基于当前观察和记忆，更新对任务的理解，把大目标拆成子任务）和**工具选择**（从可用工具库里挑下一步该调哪个、参数是什么）。行动则通过执行器落地——通常是调用代码解释器、搜索 API 这类数字工具。

这个循环的名字你可能已经听过：**Agent Loop（智能体循环）**。材料的核心主张是：智能体的“自主性”不在某一次聪明的回答里，而在循环本身——它让每一步行动的结果都能回到决策者眼前，形成持续逼近目标的过程。

### 3.3 模型和环境之间怎么对话：Thought-Action-Observation

为了让 LLM 能驱动这个循环，工程上需要一套**交互协议（Interaction Protocol）**，规定模型的输出长什么样。材料展示的协议是 T-A-O 格式：

```text
Thought: 用户想知道北京的天气。我需要调用天气查询工具。
Action: get_weather("北京")
```

`Thought` 是决策过程的“快照”——模型用自然语言写出它怎么分析现状、怎么拆解问题、下一步打算做什么；`Action` 是决定对外部世界施加的操作，通常写成函数调用。一个外部**解析器（Parser）**负责从模型输出里抓出 Action 并真正执行对应的函数。

行动返回的原始数据（例如一段 JSON——JSON 是程序之间交换数据的结构化文本格式）往往冗长且不符合模型的语言习惯，所以“感知”环节还有一个传感器式的角色：把原始输出整理成一句简洁的自然语言观察，再送回循环：

```text
Observation: 北京当前天气为晴，气温25摄氏度，微风。
```

至此协议闭合：模型产出 Thought+Action → 解析器执行 → 环境返回数据 → 封装成 Observation → 进入下一轮 Thought。LLM 的语言推理能力，就这样和外部世界的真实信息、真实工具接上了。

## 4. 从零搭一个最小 Agent：一次 5 分钟的动手体验

理论之后，材料用一个“北京天气→推荐景点”的旅行助手，演示了最小 Agent 的四个零件。

**零件一：指令模板（系统提示词）**。这是给模型的“说明书”，声明三件事：角色（你是智能旅行助手）、可用工具（`get_weather(city)` 查实时天气、`get_attraction(city, weather)` 搜景点推荐）、输出格式（每次只输出一对 Thought-Action；要么调用工具，要么用 `Finish[最终答案]` 结束）。这段模板正是**提示工程（Prompt Engineering）**的入口：模型的所有行为边界，先靠文字立起来。

**零件二：两个真实工具**。`get_weather` 调用免费的 `wttr.in` 天气服务，`get_attraction` 调用 Tavily 搜索服务，二者都把原始返回整理成自然语言。注意这里的实现模式：工具出错不会让程序崩溃，而是返回带“错误:”前缀的文本，让模型下一轮能看到失败原因。

**零件三：统一的模型调用层**。材料用了一个 `OpenAICompatibleClient`——只因为主流 LLM 服务（OpenAI、Azure，以及 Ollama、vLLM 等开源框架）普遍兼容 OpenAI 的接口格式，所以同一段代码可以换底座。对非程序员读者，只需理解一个要点：决策大脑是可替换的，循环和工具不需要跟着换。

**零件四：执行循环**。主循环做的事情很朴素：把历史拼成完整提示词 → 让模型输出一对 Thought-Action → 用解析规则抽出 Action → 如果是 `Finish[...]` 就结束，否则查工具表执行并追加 Observation → 进入下一轮。代码里还设了最大 5 轮——这是防止模型绕圈子的安全阀；解析失败时，程序会把“无法解析 Action，请严格按格式输出”作为观察喂回模型，而不是崩溃。

把四件零件拼起来，跑一次的真实过程是三轮：第一轮 Thought 决定先查天气，执行 `get_weather(city="北京")`，得到“晴、26 摄氏度”；第二轮根据天气搜索景点，得到颐和园与长城两条推荐；第三轮判断信息已足够，输出 `Finish[...]` 一段完整回答。材料由此总结：一个最小 Agent 的核心是“**工具 + 提示工程**”的组合，它演示的能力恰好四项——**任务分解、工具调用、上下文理解、结果合成**。这也是 LangChain、LlamaIndex 这类主流框架的设计精髓：它们做的不是让模型更聪明，而是把“工具注册 + 循环调度 + 结果回填”这层脚手架做扎实。

## 5. 放进应用：它是工具，还是协作者？

### 5.1 两种主流协作模式

材料把智能体的应用方式分成两类，本质区别是“谁握方向盘”。

第一种是**作为开发者工具**：智能体嵌进人的工作流，增强而不是取代人。材料列举的四个产品正好展示了四种路径——GitHub Copilot 作为编辑器里的实时补全（外加对话式扩展）；Claude Code 作为终端里的编码助手，能理解整个代码库并执行编辑、测试、调试；Trae 定位轻量快速、适合频繁迭代的 AI 编程工具；Cursor 则干脆把自己做成 AI 原生的代码编辑器，从设计之初就把 AI 交互放在核心。共同趋势是：AI 正在进入软件开发的整个生命周期，但人类仍然在流程里做判断。

第二种是**作为自主协作者**：用户把高层级目标直接委托出去，智能体像一个项目成员那样规划、执行、反思、交付。这个方向上涌现的框架可以归纳成几条架构路线：

- **单智能体自主循环**（如 AgentGPT 这类早期范式）：一个通用智能体自我提示、不断迭代，去啃开放式大目标。
- **多智能体协作**：要么是角色扮演式对话（如 CAMEL，让“程序员”和“产品经理”两个角色按协议对话），要么是组织化工作流（如 MetaGPT、CrewAI 模拟虚拟公司，每个智能体有职责和标准作业流程），要么是更灵活的对话网络（AutoGen、AgentScope 允许自定义复杂交互）。
- **高级控制流架构**（如 LangGraph）：把执行过程建模成状态图——状态是节点、转移是边，从而把循环、分支、回溯、人工介入变成可控制的结构。

### 5.2 Workflow 与 Agent 的分界线

最容易让人困惑的问题在这里：既然 Agent 这么强，是不是所有自动化都该换成 Agent？材料用一个反例说清边界。

**Workflow（工作流）**的本质是“预先编排”：把步骤和判断条件写死，例如报销审批——500 元以下经理批，500 元以上加财务总监，定制商品一律拒绝。每一步、每个分支都可预期、可审计。

**Agent** 的本质是“目标导向的自主系统”：不写死“晴天就推荐颐和园”这类规则，而是把“查天气→根据天气推荐”的推理交给模型实时完成。天气变成雨天，模型会自动换成国家博物馆。这种“基于实时信息动态推理”的能力，正是 Agent 相对 Workflow 的核心增量。

所以判断标准不是“谁先进”，而是**规则能不能被预先穷举**：流程固定、判断标准明确、需要稳定一致和完整追溯的任务，Workflow 更合适；需求模糊开放、环境动态变化、每一步都依赖实时判断的任务，Agent 更有优势。材料布置的思考题里已经点出第三种可能——方案 C：用 Workflow 兜住稳定的骨架，把需要判断力的环节留给 Agent，各取所长。

## 6. 常见误解

**误解一：智能体就是聊天机器人，或者说就是大模型。** 聊天机器人只完成“文字进、文字出”；智能体的定义要求感知环境、通过执行器改变环境，并围绕目标闭环运转。大语言模型是智能体的“大脑”，但大脑不是身体——没有循环、工具和环境接口，模型只会说话，不会做事。这也是材料从头到尾把“感知-思考-行动-观察”放在核心位置的原因。

**误解二：反应式低级，规划式高级，所以想得越久越聪明。** 安全气囊不需要深思熟虑，高频交易等不起推演；规划式智能体在环境剧变时可能“想完了，时机也过了”。真正的设计问题是匹配：什么任务需要毫秒级反应，什么任务值得花时间推演，以及如何用混合架构把两者叠起来。LLM 智能体“规划-反应”的微循环就是这个匹配的现代答案。

**误解三：Workflow 已经过时，Agent 应该接管一切。** Workflow 的价值不在技术含量，而在可预期与可审计：审批流程里每一步都有据可查，这正是它该在的场景。Agent 的自主性在规则清晰的任务里反而是风险——它可能做出有创造性但不符合合规要求的决定。材料给出的正确姿势是看任务的开放度，而不是赶时髦。

**误解四：符号主义和亚符号主义必须二选一。** 这场争论延续了半个多世纪，但材料和近年实践给出的方向是“和解”：神经网络负责从数据里学会模式，符号负责把推理步骤变成可检查、可操作的结构。LLM 智能体同时具备两者——用神经网络理解语言，用结构化的 Thought、Action、API 调用完成逻辑链条。

## 7. 收束

把这一章压缩成一句话：**智能体是在环境中以目标为导向闭环行动的主体；LLM 是它的大脑，Agent Loop 是它的骨架，工具是它的手脚，T-A-O 协议是它和世界对话的语言。**

读完材料后，可以用三组问题去检验任何一个自称“智能体”的系统：

- 它有没有完整的闭环？能否感知环境、做出决策、通过执行器行动、再让结果回到决策中？
- 它面对的环境是什么样？部分可观察、随机、动态、多智能体共存——每一条特性，系统有没有用记忆、探索、监控或快速迭代去回应？
- 这个任务该用 Workflow 还是 Agent？判断依据是规则能否被预先穷举，而不是哪个词听起来更先进。
