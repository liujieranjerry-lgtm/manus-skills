# AI Selflearning（通用知识版写作）

把用户提供的技术材料整理成一篇“聪明但没有代码背景的人能深入学”的中文知识文章。文章只依据给定的材料（链接、本地文件或粘贴文本）写作，不读取、不比对用户的既有笔记；如果用户没有提供材料，先问材料来源，不要凭主题臆造内容。

## 产出完成标准

每次交付前逐项确认，全部通过才算完成：

- **独立可读**：正文本身能讲清道理，读者不必翻原文，也不必依赖任何外部笔记。
- **企业级密度**：核心概念都包含定义、分类/边界、判断标准、术语陷阱、真实产品或案例。
- **术语内嵌**：技术名词在首次出现处解释，融入正文；没有割裂的术语表。
- **结构完整**：递进骨架（立靶 → 分层 → 分界 → 实例 → 常见误解 → 收束），结尾有“误解一/二/三”板块和可带走结论。
- **忠实材料**：整理不曲解材料观点；增补的解释与“材料原本说了什么”可区分，不把推测伪装成材料内容。
- **事实干净**：所有具体断言都已核验、或已降级为“据我了解/需确认”、或已删除（见 [fact-discipline.md](references/fact-discipline.md)）。
- **核验可查**：交付说明里附核验说明，讲清关键断言来自材料还是补充核验、哪些存疑，读者能据此核查。
- **语言达标**：面向聪明非程序员；不用职业视角；不灌水、不重复；篇幅不设限，连贯优先。

## 工作流

### 1. 定材料单元与交付

先确认两件事：**材料单元**（本次要整理的连贯材料是哪一份）和产出放哪里（直接在回复中给 / 在工作区写成 Markdown / 同步 Notion）。只有用户没说清且两种解读会显著影响结果时才问。

材料单元的默认规则：一个连贯学习单元 = 一篇文章、一个章节、一个子目录，或“一个 README + 它引用的代码”。当用户只给了索引页、仓库根目录或课程首页时，不要默认通吃整份材料——先列出候选单元（章节 / 子目录 / 页面），让用户指定要整理哪一个；除非用户明确说“覆盖整份”，才做多单元处理。多单元处理（如整个课程或仓库）的输出形态是课程地图或逐单元梳理清单，不是把多个单元硬塞进一篇递进文章。

产出默认在本地工作区写成以主题命名的 `.md` 文件，否则在回复中给出。Notion 同步仅在用户明确要求且连接可用时执行。

### 2. 消化材料

通读材料单元，提炼它真正在讲什么：主线论点、分层结构、关键概念、可展开的边界与案例。材料是仓库或站点时，先读目录和 README 定位本单元，再只读该单元引用到的文件（说明、代码），不要整仓扫描。内部整理一份“本文要覆盖的概念清单”，并标出哪些术语是首次出现、需要解释。完成标准：你能说出这篇材料“补什么、哪些点值得展开”，且不掺入材料之外的事实。

### 3. 立骨架

按 [style-guide.md](references/style-guide.md) 的结构列出这篇文章“从哪一层到哪一层”。方向明确时骨架内部完成，直接进入写作；只有输入方向模糊或用户要求审阅时才展示骨架征求意见。

### 4. 写作

按 [style-guide.md](references/style-guide.md) 的完整规则起草。全程只依据材料写作：不写“前面课程讲过”“你在某篇笔记学过”这类衔接句，不假设读者已经知道什么；所有核心概念都在本篇内讲清楚。

### 5. 事实核验门禁

按 [fact-discipline.md](references/fact-discipline.md) 执行：先列出全文断言清单，再逐条核验或降级。门禁通过标准：正文里没有以笃定语气出现但未核验的具体断言。

### 6. 独立复查

换一个“没有代码背景的读者”的视角通读全文（必要时对照原文），按 style-guide 的自检清单逐项过，发现问题改到通过为止。复查时不要只相信自己写作时的判断——术语覆盖、逻辑衔接、事实语气、材料忠实度都要单独过一遍。

### 7. 交付

按第 1 步的约定产出。用户要求同步 Notion 时，创建独立页面（不与既有页面合并），表格用 Notion 可识别的分行 HTML 格式。

交付时附一段简短核验说明（3–5 条，放在给用户的交付说明里，不写入文章正文）：本文基于哪份材料单元；关键断言中哪些直接来自材料、哪些是讲解性补充且已核验、哪些降级或存疑。

## 参考文件

- [style-guide.md](references/style-guide.md)：结构骨架、术语处理、代码解读、语言规则与自检清单。每次写作都读。
- [fact-discipline.md](references/fact-discipline.md)：断言分类、核验流程与降级规则。每次写作后必读并执行。
- [example-knowledge-article.md](references/example-knowledge-article.md)：现行规则下的完整范本（hello-agents 第一章产物），示范递进结构、企业级密度与常见误解板块。

## 边界

- 不读取、不引用用户既有笔记，不写“第几课学过”式的衔接句。
- 代码解释遵循 `code-explainer` skill 的叙事方法，不要另起一套。
- 本 skill 只管写作流程与质量，不扩大授权范围：没有用户明确要求时不修改 Notion、不发布、不改动用户的其他文件。
- 术语解释、代码解读只在文章需要的范围内出现，不单独输出术语表或逐行注释表。
